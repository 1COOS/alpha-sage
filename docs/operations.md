# 运行与恢复

## 首次初始化

```bash
cp .env.example .env
make install
make init-db
```

`make init-db` 会执行全部 Alembic 迁移并建立：

- `paper-main`，初始现金 1,000,000 CNY；
- 默认冠军 `alpha-sage-cognition-v1`；
- A 股交易规则版本、来源注册表和安全策略；
- 默认暂停状态。

## 配置模型

推荐在设置页保存 API Key，密钥进入操作系统密钥环。无可用密钥环时，在仅本机可读的 `.env` 中设置 `OPENAI_API_KEY`。模型设置还包括 Base URL、Responses/Chat Completions 模式、推理模型、快速模型和每日请求预算。

保存前可点击“测试连接”。测试使用表单当前值，因此能验证尚未保存的 Base URL、模式和模型名；如果当前输入了 API Key，也只用于本次测试。测试会真实调用推理模型和快速模型各一次，成功不会自动保存。页面只显示“API Key 已配置/未配置”，永不回显密钥。详细优先级和故障分类见[模型配置](model-configuration.md)。

## 初始化数据

完整同步：

```bash
make sync-history
```

小规模来源验证：

```bash
cd backend
uv run alpha-sage sync-history --years 5 --limit 10
```

同步按标的串行执行，避免 SQLAlchemy Session 和 BaoStock 登录状态并发污染。股票与 ETF 分段获取后合并去重；每个标的必须通过双源价格、上市时间和流动性门槛。

## 启用与暂停

先执行 `make preflight`。全部 PASS 后，只能由用户在界面点击“自检并启用”，或显式调用启用 API。聊天、Agent 和调度器均不能绕过该步骤。

暂停后不再产生新判断或买入。组合回撤达到 18% 时系统自动暂停新开仓；已经存在的硬风控卖出订单仍允许执行。用户手动暂停则停止全部交易动作。

## 调度时间

交易所时区为 `Asia/Shanghai`：

- 盘后研究：工作日 15:20；
- 盘中复核：09:30–11:30、13:00–14:55，每 5 分钟；
- 到期归因：工作日 15:40；
- 周度规律：周五 18:00；
- 月度挑战者：每月第一个周五 19:00。

调度、交易日判断和界面时间统一按北京时间执行。数据库仍保存 UTC 绝对时间，API 对外统一
返回 `+08:00`；因此服务进程或浏览器处于其他系统时区时，不应改变任务触发时刻、任务排序或耗时。

调度任务 `coalesce=false`，误触发宽限 60 秒。电脑休眠或服务停止期间错过的盘中任务不会在恢复后补跑，因此不会补造本应发生在过去的成交。

## 任务队列与任务中心

历史同步、盘后研究、盘中复核、归因、周度总结、月度挑战者和模型测试共用一个本地单线程队列。手动触发和调度触发都会写入 `agent_runs`，页面刷新后仍能从任务中心恢复。活动任务每 2 秒刷新阶段、进度、当前标的或模型和动态耗时。

任务耗时按带时区的绝对时刻计算。若后端返回缺少时区的时间，界面显示“耗时未知”并等待契约修复，
不得把无时区时间按浏览器本地时区猜测。

同类活动任务不会重复提交。盘中高频调度遇到任何活动任务时记录为 `SKIPPED`，不会排队等待后补；其他任务按提交顺序串行运行。服务停止时不自动重放任务，重启后遗留的 `PENDING`/`RUNNING` 会改为 `FAILED`，必须由用户核对后重新触发。

任务中心与按钮附近的成功、失败、阻断信息不会自动消失。用户关闭只把任务 ID 记入浏览器 `localStorage`，不会删除后端 `AgentRun` 历史。

## 恢复流程

服务恢复后：

1. 打开任务中心，检查因重启标记失败的任务、最后阶段和阻断原因；
2. 再次执行历史同步，以公开来源补齐可证明的数据缺口；
3. 执行 `make preflight`；
4. 检查待成交订单。系统只会使用恢复后的最新完整 5 分钟行情，不回填停机期间成交；
5. 如账户由用户手动暂停，必须再次人工启用。
